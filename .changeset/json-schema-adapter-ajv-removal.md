---
'@mastra/schema-compat': major
---

Removed Ajv from the JSON Schema adapter, which now validates with `@cfworker/json-schema`. The `ajvOptions` option and the `getAjv()` method are removed, and Ajv customization has no replacement. Drop the option:

```ts
// Before
const schema = toStandardSchema(jsonSchema, { ajvOptions: { strict: false } });
// After
const schema = toStandardSchema(jsonSchema);
```

Ajv options that changed the value, such as `coerceTypes`, `useDefaults` and `removeAdditional`, are gone too: the validated value is now returned exactly as passed. Convert strings to numbers, fill defaults or strip extra properties before calling `validate`, for example with a Zod schema's `z.coerce` and `.default()`, or by hand.

Code that called `getAjv()` to add keywords or formats should express the rule with a keyword the adapter checks, such as `pattern`, `enum` or `minimum`, or validate the value separately. Do not move a custom format to the `format` keyword: the adapter never checks `format`, on any subschema.

Validation message texts are the new validator's own. For example, a value that fails `oneOf` now reads `Instance does not match exactly one subschema (2 matches).` where Ajv wrote `must match exactly one schema in oneOf`. Issue paths are unchanged. Code that matches on a message text must be updated.

The adapter now accepts only a fixed list of keywords for each dialect and refuses any other schema when it compiles it. A schema without `$schema`, or with draft-07's, is draft-07. A schema with `https://json-schema.org/draft/2020-12/schema` is 2020-12, as `MCPClient` marks every tool schema that names no dialect. The validation result then carries one issue, `Schema validation error: <keyword> at "<pointer>" <reason>, so the schema is refused`. The issue names the keyword and its JSON Pointer, but never the schema's values or the tool's arguments.

The list is: `type`, `properties`, `required`, `items`, `additionalProperties`, `propertyNames`, `allOf`, `anyOf`, `oneOf`, `enum`, `const`, the numeric bounds, the length, item and property counts, `pattern`, `nullable`, `format` (not checked), `$ref`, `$defs`, `definitions`, the annotations `title`, `description`, `default`, `examples` and `example`, plus `discriminator`, Composio's `human_parameter_*` and `file_*` keys, and any key starting with `x-`. A draft-07 schema may also use `additionalItems` and a non-empty array under `items` (a tuple). A 2020-12 schema may also use `prefixItems`, `dependentRequired`, `$comment`, and `$id` at the root as an absolute URI. Every other keyword is refused, including `not`, `if`, `multipleOf`, `uniqueItems`, `contains`, `minContains`, `maxContains`, `unevaluatedProperties`, `unevaluatedItems` and `dependentSchemas`.

A keyword stays on a dialect's list only if this validator and fork main's Ajv for that dialect gave the same answer for it; a keyword where they differed was taken off the list rather than patched. The last comparison run checked this adapter against fork main's Ajv with random schemas, built from the listed keywords, refused keywords and listed keywords holding values of the wrong type, each against generated values: four seeds per dialect, 212,000 draft-07 and 248,000 2020-12 comparisons. In none did this adapter accept what fork main refused. In the other direction, every case fork main accepted and this adapter did not (38,832 of 460,000) was a schema refused by the list, mostly for `not`, `uniqueItems`, `multipleOf`, `dependentSchemas`, a dialect's own keyword or a prototype name; no listed schema gave a different answer for a value. A 1,954-tool corpus of real MCP and Composio tool schemas uses none of the removed keywords. Because the list refuses these keywords before validation, the validator differences described in the other `@mastra/schema-compat` entry of this release apply only to the listed keywords.

Fork main's Ajv is `new Ajv({ allErrors: true, strict: false })`, or `Ajv2020` for a 2020-12 `$schema`, in `json-schema.ts:209-217`. Compared with it:

- Refused here, accepted by fork main: `not`. Ajv compiled `not` without `allErrors`, and the two validators gave different answers for some schemas: for example, this validator accepted `{}` against `{ not: { required: [''] } }`, which fork main refused. So `not` left both lists. A schema that needs it can often be written with `oneOf`: `oneOf: [true, S]` refuses exactly the values `S` accepts. The Factory test fixture in `projects-concurrency.test.ts` was rewritten that way because `not` is now refused while fork main accepts it. Its three cases keep the same response statuses and issue paths; only the message text differs.
- Refused here, accepted by fork main: a `$schema` other than draft-07 or 2020-12 at the root. Fork main validated, for example, a 2019-09 schema with its draft-07 Ajv. A string `$schema` below the root is ignored, as fork main ignored it.
- Refused here, accepted by fork main: an `$id` in a draft-07 schema, and a root `$id` that is not an absolute URI without a fragment.
- Refused here, accepted by fork main: an `$id`, `$anchor` or `$dynamicAnchor` string below the root, in a schema or in an object Ajv's reference walk entered, such as an annotation under `example` or an `x-` key. Ajv registered each one and threw when one was malformed or repeated an ID, an anchor or a registered metaschema ID; it accepted the rest. This validator resolves none of them, so none is accepted. The root `$id` is the one exception.
- Refused here, accepted by fork main: `if`/`then`/`else`, `patternProperties`, `dependencies`, `multipleOf`, `uniqueItems`, `contains`, `minContains`, `maxContains`, `unevaluatedProperties`, `unevaluatedItems`, `dependentSchemas`, `additionalItems` in a 2020-12 schema, `id`, `$anchor`, `$dynamic*` and `$recursive*`, and any other key not on the list, plus the 2020-12 keywords above in a draft-07 schema. Fork main applied or ignored these under `strict: false`. A draft-07 Composio output schema with a tuple-style `prefixItems` (`GITHUB_GET_THE_HOURLY_COMMIT_COUNT_FOR_EACH_DAY`) is refused for this reason; fork main's draft-07 Ajv ignored the keyword.
- Refused here, accepted by fork main: a `$ref` other than `#` or a member of the root's `$defs` or `definitions`.
- Refused here, accepted by fork main: a property, `required` or `dependentRequired` name that `Object.prototype` also holds (such as `__proto__`, `constructor`, `toString`, `valueOf` or `hasOwnProperty`), and a `$defs` or `definitions` name, or a `const`/`enum` key, named `__proto__`, `constructor`, `toString` or `valueOf`.
- Refused here, accepted by fork main: a value that JSON cannot carry (a non-finite number, a `Date` or another object whose prototype is neither `Object.prototype` nor `null`, a sparse array, a cycle, a function, a `bigint` or a symbol), and a value holding a property read through a getter or setter, which this validator could read more than once. Where the schema compares values with `const` or `enum`, an object with a `null` prototype and an array subclass are refused too, because Ajv's equality compared constructors and this validator's does not; elsewhere they are accepted.
- Refused here, accepted by fork main: a schema holding an own key that is not enumerable or is a symbol, or a property read through a getter or setter, anywhere; and, inside `const` or `enum` data, an object whose prototype is neither `Object.prototype` nor `Array.prototype` (such as a `Date`, a class instance or an object with a `null` prototype). Ajv and this validator read such schemas differently.
- Refused here, accepted by fork main: a `Proxy`, as a schema or anywhere in one, or in a validated value. This needs the runtime to tell a `Proxy` apart, which Node and Bun do through `util.types.isProxy`. In other runtimes, such as browsers, Deno without Node compatibility and Cloudflare Workers, a `Proxy` is not recognised and is read like the object it wraps.
- Before these refusals were added, a counter that refused nothing recorded every schema and value that would have hit them, over the full test suites of `@mastra/core`, `@mastra/mcp`, `@mastra/schema-compat` and the Factory, and over PapersFlow's tool registration and argument paths. It recorded none.
- Refused here and by fork main, which refused the schema against its metaschema or threw while compiling it: a listed keyword holding a value of the wrong type, such as a boolean `exclusiveMinimum`, `required: true` or an empty `enum`; a hole or `undefined` member in `required`, `type`, `allOf`, `anyOf`, `oneOf`, a tuple `items`, `prefixItems` or an `enum` of fewer than 200 members; `nullable: true` beside a frozen `type` list; a root `$id` that is a URN without a namespace (such as `urn:x`) or that names a metaschema Ajv had registered; a draft-07 `enum` that repeats a member; and a `$defs` member named `$id` that Ajv read as the scope of a `$ref` into `$defs`.
- Refused here, where fork main overflowed its stack or recursed: a loop of `$ref`, `allOf`, `anyOf` or `oneOf` that reads the same schema at the same value and that the root reaches. A loop only inside an unused definition is accepted, as fork main never compiled it.

A keyword whose value is `undefined` counts as absent, as Ajv read it. A property whose value is `undefined` in a validated value is handled as fork main handled it (see the other `@mastra/schema-compat` entry).

PapersFlow import facts, checked on PapersFlow origin/main 1bc4cdd6a0. No PapersFlow source imports `@mastra/mcp`. One test, `apps/doxa-runtime/tests/mcpSdk.integration.test.ts`, imports the upstream MCP SDK's `Client` and `StreamableHTTPClientTransport`. That is not `MCPClient` and never reaches this adapter. PapersFlow's run-scoped Parallel MCP surface (`apps/doxa-runtime/src/parallel/mcpRunScopedParallel.ts`) only serves tool schemas, so it adds no schema source.
