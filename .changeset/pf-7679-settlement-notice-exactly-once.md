Harness v1: a delegated settlement notice in `wake` mode (`subagents.onDelegatedSettlement: 'wake'`) now reaches the parent model exactly once.

- **Timing change:** a settlement wake now waits until the parent has no running turn, parked interaction or queued turn before it claims and delivers the notice. Delivery timing changes; the exactly-once contract does not.
- **No duplicate through history:** if a fresh parent run of the agent whose memory saved the reminder row started after the save, that run already read the notice from history, so no wake is sent. Before, such a run and the wake could both deliver it.
- **No loss to a caller turn:** if a caller turn takes the idle slot after the wake claimed the notice, the notice is owed again and the wake waits for that turn to end. Before, the claimed notice was sent into that turn unlabelled, and a parent without memory could lose it when the wake was refused after the claim. A parent turn that began after the save also no longer suppresses the wake when no fresh run read the row (always the case without memory).
- **Wake grants (with `sessions.terminalHandoff.wakeFinalizer`):** a wake that runs after a caller turn is checked for a grant when it runs, so it can get one and stage a wake intent. If a grant was given up after its admission (a lost slot, a `discard`, a dispatch that threw) and the notice is owed again, the retry, in this process or by the next owner, runs without a grant and stages no intent; the given-up grant stays cancelled. A crash between a wake's grant admission and its delivery leaves that admission to recovery, which settles it as an aborted wake intent, and the next owner still delivers the notice once, without a grant.
- **Close, shutdown and crash:** a close, Harness shutdown or crash while the wake waits leaves the notice owed, and the next owner of the session delivers it.
- **Remaining cases:** a crash during the claim write itself can lose the wake of a parent without memory. A failed write when the claimed notice is put back owed (after a lost slot or a refused dispatch), or a Stop together with a crash during that write, loses the wake; with memory the row still reaches the next parent turn. A dynamic or inherited memory, or a row saved to another mode's memory, is never treated as already delivered, so a caller run may read the row and the wake may still follow. A fresh run dispatched before the row was saved is not treated as having read it, even if it loads history after the save, so the wake may follow it and the notice can reach the model twice. A fresh run is treated as having read the row once the runtime accepts it, even if it fails before loading memory or its memory does not recall recent messages; the row then reaches the next parent turn instead.
