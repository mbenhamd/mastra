Harness v1: a delegated settlement notice in `wake` mode (`subagents.onDelegatedSettlement: 'wake'`) now reaches the parent model exactly once.

- **Timing change:** a settlement wake now waits until the parent has no running turn, parked interaction or queued turn before it claims and delivers the notice. Delivery timing changes; the exactly-once contract does not.
- **No duplicate through history:** a parent run in this process that loaded the reminder row into its model context already delivered the notice, so no wake is sent. Runs are recorded when their input processors finish, by the row's stored id, whatever memory instance the agent resolved. Before, such a run and the wake could both deliver it.
- **Claim lease:** the wake claims the notice before it dispatches (`settlement.notice.claim` in the task metadata, no schema change). The notice stays owed under the claim until the accepted wake acknowledges it. A claim is valid only while its claimer holds the session lease; the claimer dispatches only while it still holds the lease, and the next lease holder takes over a claim whose claimer lost the lease or crashed. A Stop on a claimed notice downgrades it to `remind` and keeps the claim, so no wake follows.
- **No loss to a caller turn:** if a caller turn takes the idle slot after the wake claimed the notice, the claim is cleared and the wake waits for that turn to end. Before, the claimed notice was sent into that turn unlabelled, and a parent without memory could lose it when the wake was refused after the claim. A claim that cannot be cleared is given up in this process, so the next reconcile pass takes it over.
- **Wake grants (with `sessions.terminalHandoff.wakeFinalizer`):** a wake that runs after a caller turn is checked for a grant when it runs, so it can get one and stage a wake intent. If a grant was given up after its admission (a lost slot, a `discard`, a dispatch that threw) and the notice is owed again, the retry, in this process or by the next owner, runs without a grant and stages no intent; the given-up grant stays cancelled. A crash between a wake's grant admission and its delivery leaves that admission to recovery, which settles it as an aborted wake intent, and the next owner still delivers the notice once, without a grant.
- **Close, shutdown and crash:** a close, Harness shutdown or crash while the wake waits, or after it claimed the notice, leaves the notice owed, and the next owner of the session delivers it.
- **Remaining cases:** a run started by another process on the parent thread is never seen as having loaded the row, so a wake may follow it and the notice can reach the model twice. A run that loaded the row counts as delivered even if a later processor trims the row or the run fails before its model call; the row then reaches the next parent turn. A crash between a run loading the row and the acknowledgement re-saves the row and wakes again (a duplicate, not a loss). A claimer that dispatched the wake and then lost its lease, closed or crashed before the acknowledgement leaves its claim, so the next lease holder may wake a second time; a process pause between the claimer's lease check and the provider request can do the same. Two Harness instances in one process that share one `ownerId` do not see each other's live claims, so one may take over the other's claim and wake a second time. A wake whose dispatch the runtime neither confirms as a wake nor refuses (an acceptance timeout, or another answer such as blocked) is counted as delivered and logged at error level, so a parent without memory may lose that notice.
