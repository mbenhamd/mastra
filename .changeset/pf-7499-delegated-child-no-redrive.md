Fixed Harness restart recovery re-running a delegated subagent that was killed mid-run. When a process restarts and finds a `task_delegate` child whose run the process that died had already started dispatching, the child is now interrupted instead of run again: the plan task fails with `harness.run_interrupted`, the child is closed, and the parent is no longer held busy by a second run of that work. A delegation that never started still runs once, and one waiting for approval still waits. The interrupted run's completion (`agent_end`, `run_completed` and its run summary) is published before the child closes, whichever path closes it (settlement, an explicit close, a `subagent` cancel or a parent Stop), and before the task settles; a failed or crashed publication refuses the close and is retried, a closed child that still owes it is reopened to publish it, and closing a cold parent or child from another process materializes a child that still owes one so its close publishes it. A failed read of the child's result no longer lets recovery settle the task without it. Storage adapters that do not enforce the session lease on recovery writes (`supportsDispatchRecovery` is false) keep the previous re-attach behaviour instead of writing an unfenced interruption.
