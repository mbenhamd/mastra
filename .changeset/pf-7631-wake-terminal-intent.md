Harness v1: a settlement wake turn (`subagents.onDelegatedSettlement: 'wake'`) can now stage a terminal intent. Register `sessions.terminalHandoff.wakeFinalizer` (its id must differ from the message finalizer's). A wake turn that still holds its idle slot at dispatch (no caller turn began, no run is active), and whose reminder row was saved by the dispatching agent's own fixed memory instance with no mode change since, then runs as the reserved wake run under a Harness-minted grant, `harness-wake:<wakeNoticeId>` at generation 1, and is committed under the wake finalizer. Any other wake (a caller turn took the slot, a memory-less parent, a row saved to another mode's memory, function or inherited memory, a mode switch) stages no intent and is sent as before, so a caller run still receives the notice as its next model input. A grant given up after its admission (a caller turn or a mode switch during the admission, or a Stop, edit, delete or eviction before the dispatch) is cancelled: no terminal result and no intent; its `harness-wake:` reservation is settled failed with `harness.terminal_cancelled`. If storage refuses the cancel, recovery settles the wake as interrupted (an aborted wake intent is possible). The stored payload is a `HarnessWakeTerminalPayload`: `origin: 'wake'`, `wakeNoticeId`, `runId`, `taskId`, `subagentSessionId`, `outcome`, and `reply` (your finalizer's payload). If the process dies after the wake run ends but before the intent is written, the next owner of the session settles it from the staged output without re-running the model.

`message()`, `admitMessage()`, `signal()`, `queue()` and `admitQueue()` now reject an `admissionId` (and `message()`/`admitMessage()` an `executionAuthorityGrant.key`) in the reserved `harness-wake:` namespace. If a wake's terminal commit fails, the Harness emits an `error` event and retries with bounded backoff; if it still fails, `close()` is refused until the wake settles, and the admission stays durable for the next owner. A wake run that fails by its own output first emits an `error` event with its `runId` and error code; if its commit never lands, the next owner settles it as `aborted` with `harness.run_interrupted`, so that event is the only record of the run's error. A wake turn that suspends and is resumed commits through the same retry; if that still fails, the response call rejects and the interaction stays parked. A retried response settles it; once the interaction is due, `close()` settles it from the staged output. If only that commit fails, `close()` is refused with `HarnessSessionLockedError` and the interaction stays with its owner, which settles it once storage recovers. If storage is also unavailable for close's read of the wake admission, `close()` rejects with the raw storage or terminal-handoff error (for example `harness.terminal_pending`).

New `@internal` member: `Agent.__fixedMemory()` returns the agent's own fixed memory instance without resolving it (undefined for function, inherited or no memory). It ships in the `Agent` type declarations (`dist/agent/agent.d.ts`). The wake path needs it to prove that the wake's reminder row was saved by the dispatching agent's own memory instance before it keeps a wake grant.

`claimTerminalIntents` accepts `finalizerIds` to claim only intents of those finalizers. Per-session delivery order now holds within one finalizer id, so an unsettled intent of one kind never holds back another kind. This also applies without the filter: if you rename your finalizer and drain the old id through `settleOnly`, intents under the old and new ids in one session are no longer ordered against each other. Keep one finalizer id across versions to keep their order.

```ts
const wakes = await storage.claimTerminalIntents({
  consumerId: 'wake-consumer',
  limit: 10,
  finalizerIds: ['my-app.chat-wake'],
});
```
