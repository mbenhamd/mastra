# SkillSearchProcessor

The `SkillSearchProcessor` is an **input processor** that enables on-demand skill discovery and loading. Instead of injecting all skill metadata into the system prompt upfront (like `SkillsProcessor`), it gives the agent `search_skills` and, by default, `load_skill` to find and load skills on demand. This reduces context token usage when workspaces have many skills.

By default, when you attach only `SkillSearchProcessor` to an agent with a skill-enabled `Workspace`, the agent treats skills as on-demand:

- The default eager `SkillsProcessor` isn't auto-added.
- `search_skills` and `load_skill` are exposed for discovery and instruction loading.
- Overlapping `skill` and `skill_search` tools are hidden.
- `skill_read` remains available so the agent can read supporting skill files such as references, scripts, and assets.

If you explicitly configure `SkillsProcessor` alongside `SkillSearchProcessor`, the agent preserves the eager `skill` and `skill_search` tools as an opt-in path.

## Usage example

```typescript
import { SkillSearchProcessor } from '@mastra/core/processors'

const skillSearch = new SkillSearchProcessor({
  workspace,
  storage: 'context',
  search: {
    autoLoad: true,
    topK: 3,
    minScore: 0.1,
  },
})
```

## Extended usage example

```typescript title="src/mastra/agents/skill-agent.ts"
import { Agent } from '@mastra/core/agent'
import { SkillSearchProcessor } from '@mastra/core/processors'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './project' }),
  skills: ['skills'],
  bm25: true,
})

const skillSearch = new SkillSearchProcessor({
  workspace,
  storage: 'context',
  search: {
    autoLoad: true,
    topK: 3,
    minScore: 0.1,
  },
})

const agent = new Agent({
  id: 'skill-agent',
  name: 'skill-agent',
  instructions:
    'You are a helpful assistant. Use search_skills to find and activate relevant skills.',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
  inputProcessors: [skillSearch],
})
```

With `search.autoLoad: true`, the agent workflow is:

1. Agent receives a user message
1. Agent calls `search_skills` with keywords (e.g., "api design")
1. Matching skills activate and their instructions appear as system messages on the next turn
1. Agent follows the loaded skill's instructions

## Single-step discovery with `autoLoad`

Set `search.autoLoad` to `true` to remove the separate `load_skill` call. `search_skills` activates every returned match and emits a durable activation receipt. The instructions become available on the next model turn. `load_skill` isn't exposed in this mode, so the model can't spend turns repeatedly loading the same skill.

```typescript
const skillSearch = new SkillSearchProcessor({
  workspace,
  storage: 'context',
  search: {
    autoLoad: true,
    topK: 3,
  },
})
```

Keep `topK` small because every match adds its complete instructions to subsequent prompts. Discovery remains model-driven. Auto-load removes only the second search-to-load call.

## Loaded-skill state

The `storage: 'context'` mode records a content digest in each successful `load_skill` result, or in the marked `search_skills` activation receipt when auto-load is enabled. `SkillSearchProcessor` reconstructs loaded skills from the activation results that remain in the conversation.

This behavior has three effects:

- Loaded skills survive process restarts when the conversation history is restored.
- Editing, deleting, or regenerating past the activation result unloads that skill.
- A skill whose current content no longer matches its recorded digest stays inactive until the agent loads it again.

Send the stored conversation messages to the agent when you resume a thread. The default `storage: 'in-memory'` mode preserves process-local behavior for existing applications, but it doesn't survive a restart or follow message-history edits.

`clearState()` and `clearAllState()` clear only in-memory state. In context mode, remove the relevant activation result from the conversation instead. `dispose()` releases the in-memory cleanup timer and can be called more than once.

## Workspace file tools

`SkillSearchProcessor` loads skill instructions into the conversation. It doesn't block workspace file tools from reading files.

Use `skill_read` for supporting files that belong to a loaded skill, such as files under `references/`, `scripts/`, or `assets/`.

Reserve workspace file tools such as `mastra_workspace_read_file` for explicit file inspection or editing workflows. During normal task execution, the agent doesn't need to read the same `SKILL.md` file after `load_skill` succeeds.

## Compared to SkillsProcessor

| | SkillsProcessor | SkillSearchProcessor |
| - | - | - |
| Scaling | Injects all skills upfront | On-demand discovery |
| Context usage | Grows with skill count | Constant (only loaded skills) |
| Agent workflow | Skills always visible | Agent searches and loads as needed |
| Best for | Few skills (\< 10) | Many skills (10+) |
