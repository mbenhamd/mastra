# ToolResultSupersedeProcessor

The `ToolResultSupersedeProcessor` is an **input processor** that keeps only the newest result for a resource in the prompt. Each agent step sends every earlier tool result again. When a tool reads the same file, page or record a second time, the earlier copy no longer helps the model. This processor replaces it with a one-line pointer to the newer result.

The rewrite happens in the `processLLMRequest` hook and is transient: it changes only the prompt sent to the model on that call. Stored messages, memory and UI history keep every result.

## Usage example

```typescript
import { ToolResultSupersedeProcessor } from '@mastra/core/processors'

const supersede = new ToolResultSupersedeProcessor({
  tools: {
    // A later read of the same file replaces the earlier one.
    read_file: { key: ({ input }) => (input as { path?: string }).path },
    // Keep a paper's abstract and its full text apart: coverage is part of the key.
    read_paper: {
      key: ({ input, result }) => {
        const id = (input as { id?: string }).id
        const coverage = (result as { coverage?: string } | undefined)?.coverage
        return id && coverage ? `${id}:${coverage}` : undefined
      },
    },
  },
})

const agent = new Agent({
  id: 'writer',
  // ...
  inputProcessors: [supersede],
})
```

## Which results are replaced

A result is replaced only when a successful result with the same key comes from a **later model step**. Results of the same step never replace each other, and the latest step's results are always sent in full.

These results are always kept:

- errors, and results that the tool's `resultStatus` marks as failures;
- results of calls that passed through an approval;
- provider-executed results;
- results with media, unless `includeMedia` is set;
- results the processor can't match to exactly one recorded call. Tool-call IDs can repeat across turns, so each prompt result is matched to its recorded occurrence in the message list.

The pointer text doesn't name the newer call, so the replaced result reads the same on every later step. This keeps the provider's prompt cache valid after the first replacement.

## Choosing a key

The key decides what counts as "the same resource". Include everything that changes what the result covers: the project or workspace, the path, a line range, a truncation limit or whether the result is an image. Leave out values that only change between versions of the same resource, such as a content hash, when the newest version is the only one the model should use.

## Ordering with other processors

Put `ToolResultSupersedeProcessor` before any processor that caches responses by prompt, so the cache key reflects the shorter prompt. It works independently of [`ToolCallFilter`](/reference/processors/tool-call-filter): a call that filter removes isn't in the prompt and is ignored.
